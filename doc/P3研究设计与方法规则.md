# P3 研究设计与方法规则

> 本文档基于当前项目 P3 流程（`doc/P3流程详解.md`）和 2026-07-02 方法审查讨论，整合修订后的管道设计、核心规则与结论边界。
> 适合读者：接手执行、论文写作、或对 P3 方法进行进一步审核的研究者。
> 更新时间：2026-07-02

---

## 1. 研究问题与证据等级

### 1.1 研究问题（暂定）

本研究探讨 **MI 咨询数据集（MISC 标签）在 LLM 内部表征中的结构模式**，使用稀疏自编码器（SAE）作为分析工具。

**RQ1**：LLM 内部表征中，SAE latent 捕捉到了哪些与 MISC 标签相关的**输入选择性模式**？

**RQ2**：这些模式能否被**表面形式或 data artifact** 解释？还是与更复杂的**对话功能**一致？

### 1.2 证据等级定位（必须遵守）

| 层级 | 当前 P3 能达到 | 当前 P3 不能达到 |
|---|---|---|
| **输入选择性**（latent 对哪类输入激活）| ✅ 激活预测可回答 | — |
| **相关性证据** | ✅ AUC / Cohen's d | — |
| **artifact 可排除性** | ✅ 反事实验证可回答 | — |
| **表面 vs 功能 的正向归属** | ⚠️ 需两套验证合并才能支持假设 | 单一指标无法判定 |
| **MI 原则的编码** | ❌ | 需要因果干预（P5） |
| **上下文关系（RE/RES/REC）** | ❌ | 数据缺 client utterance |
| **因果机制** | ❌ | 需 P5 ablation/steering |

> **一句话定位**：P3 是"候选解释生成与初筛"，而不是"因果证明"。最终论文表述必须在此范围内。

## 2. 完整流程概览

```
Step 0  数据准备（已有：label_matrix, feature_store, records）
   ↓
Step 1  探针扫层 → 确定"概念最强层"
   ↓
Step 2  SAE 概念重构充分性确认（EV 不是证据，用探针重构充分性）
   ↓
Step 3  统计指标计算（AUC / Cohen's d / 线性探针 / 最小充分子空间）
   ↓
Step 4  Top 激活语句收集 + Evidence Packets 构建
   ↓
Step 5  GPT-4（或等效 LLM）自动解释生成（label-blind）
   ↓
Step 6  三层验证
         ├─ V1：释义改写测试（surface 变，function held）
         ├─ V2：功能翻转测试（function 变，surface 近似 held）
         └─ V3：Token 级激活分析（需重跑保存 per-token latent）
   ↓
Step 7  Feature Card 生成 + 人工审核
   ↓
Step 8  P4 latent 聚类 / P5 ablation（后续阶段）
```

> **阴性对照（贯穿全流程）**：必须同时报告 shuffled-latent baseline 和 label-definition-only baseline，任一对照打平则相应结论撤回。

## 3. 各步骤详细规则

### Step 1：探针扫层，确定目标层

**目的**：找到线性可分性最强的层，作为后续 SAE 分析的起点。

**输入**：`utterance_activations.pt`（各层 hidden states）、`label_matrix.csv`

**操作**：
- 对每一候选层，训练轻量线性分类探针（logistic regression）
- 记录各层各标签的 AUC、balanced accuracy
- 选取"综合最强层"

**硬约束**：
1. **SAE 可用层必须提前确认**。若 SAE 只覆盖部分层（如仅 layer 19），则"自由选层"无效，改为"验证固定层的探针性能是否可接受"，不得假设可在任意层使用 SAE。
2. 探针最强层 ≠ SAE 概念可解性最强层，两者不一定重合，结果要明确报告是否一致。

---

### Step 2：SAE 概念重构充分性确认

**目的**：确认选定层的 SAE 能"承载"该概念，即 SAE latent 空间可以重建探针方向。

**⚠️ 常见错误（必须避免）**：
> 用 SAE 的全局重构 EV（explained variance）来"证明 SAE 能解读该概念"——这是非逻辑推理。EV 衡量对全部激活的重构质量，与某个特定概念无关。

**正确操作**：
1. 用 SAE 重构激活：`z_recon = SAE.decode(SAE.encode(h))`
2. 在重构激活上重训探针，得 `AUC_recon`
3. 对比 `AUC_raw`（原始 hidden）vs `AUC_recon`（SAE 重构）
4. 若 `AUC_recon ≈ AUC_raw`（差距 < 约定阈值，建议 ≤ 0.03），则认为 SAE 子空间充分保留了该概念

**输出**：各标签的 `(AUC_raw, AUC_recon, delta)` 对照表

---

### Step 3：统计指标计算 + 最小充分子空间

**计算指标**：
- `AUC`（主指标，对零膨胀激活更稳健）
- `Cohen's d`（辅助，**必须注意以下限制**）
- 线性探针分类性能（precision / recall / F1 / balanced accuracy）
- `minimal_sufficient_subspace`：最少几个 latent 能逼近完整候选池的探针性能

**统计规则（强制执行）**：

| 规则 | 说明 |
|---|---|
| AUC 为主 | Cohen's d 在零膨胀分布上不稳定，仅作参考 |
| 去重或降权 | 约 1214 条重复文本必须去重或降权后再算效应量，否则重复模板制造虚高 d |
| Permutation null | 32768 latent × 多标签取 top-N，必须报 permutation null + FDR 校正 |
| Latent 选择 held-out | latent 由选择集选出后，验证集必须独立；不能在选 latent 的同一总体上"验证" |
| 低频标签警告 | SU（222 正例）、RES（516 正例）极易出现 winner's curse，其 robust_candidate 结论需额外谨慎 |

**最小充分子空间的口径**：

> `minimal_sufficient_subspace` = 预测充分性（多少 latent 能逼近探针性能），**不等于"这些 latent 就是该概念本身"**。
> 论文中必须使用"最小预测充分子空间"或"predictive sufficient subspace"措辞，禁止写成"该概念由这几个 latent 表示"。

---

### Step 4：Top 激活语句收集与 Evidence Packets

**每个 latent 的 evidence packet 包含**：

| 样本组 | 用途 |
|---|---|
| `top_activating` | 该 latent 激活最高的句子，用于归纳候选模式 |
| `high_non_target` | 非目标标签中也高激活，用于发现混淆或 artifact |
| `random_target` | 目标标签随机正例，检查覆盖度 |
| `sibling_code_contrast` | 易混相邻标签对照（如 QUO vs QUC） |
| `surface_matched_contrast` | 表面相似但非目标标签的对照 |
| `low_activation` | 低激活样例，用于 scoring |

**重复文本处理规则**：top_activating 中若出现重复文本簇，必须标注为"模板/artifact 风险"候选，不得直接用作解释证据。

---

### Step 5：自动解释生成（AI 解释器）

**解释器要求**：
1. **Label-blind**：生成解释时，解释器**不得知道**目标 MISC 标签名。否则解释器会用标签先验作答，而非 latent 结构。
2. **多次采样**：同一 latent 至少采样 3 次，报告解释的自洽性/变异程度。
3. **跨模型交叉**（建议）：至少用两种不同 LLM 各生成一版，检验解释是否模型无关。

**解释输出的口径**：

> 解释生成的候选名称（candidate_feature_name）是**假设**，不是发现。自动解释的质量评分（evidence_quality、artifact_risk）是**单一 AI 的意见**，不构成实证证据。

---

## 4. Step 6：三层验证（核心，决定 RQ2 可回答性）

三层验证的目的是用**受控输入变化**判断 latent 跟踪的是**表面线索**还是**对话功能**。

### 验证逻辑框架（2×2 矩阵）

|  | 表面形式不变 | 表面形式改变 |
|---|---|---|
| **对话功能不变** | （平凡，激活应不变） | **V1：释义改写测试** |
| **对话功能改变** | **V2：功能翻转测试** | （两者都变，无判别信息） |

**注意**："right → wrong"属于 V2（功能翻转），**不是**"反转表面模式"。混淆这两格会把判读方向搞反。

---

### V1：释义改写测试（paraphrase test）

**操作**：对 top_activating 样例，生成表面形式不同、但对话功能相同的改写版本。

**判读**：
- latent 激活**保持高** → 支持 latent 跟踪**功能/概念**（不依赖表面形式）
- latent 激活**显著下降** → 支持 latent 是**表面形式绑定**

**构造要求**：
1. 改写句必须过模型取**真实激活**（不能在文本层面推理）
2. 报告每条改写的语法可接受度（可用 LLM 打分，OOD 条目标注不纳入统计）
3. 用配对检验（paired t-test 或 Wilcoxon）报告激活变化显著性

---

### V2：功能翻转测试（function-flip test）

**操作**：对 top_activating 样例，做最小语义编辑使对话功能/效价翻转，同时尽量保留表面结构。

**典型例子（AF 肯定类）**：
- `"That's really brave of you."` → `"That's quite strange of you."` （认可→否定，表面结构near-identical）

**判读**：
- latent 激活**显著下降** → 支持 latent 对**功能/效价敏感**（favors 概念解释）
- latent 激活**基本不变** → 支持 latent 是**词汇/表面 artifact**（"brave"≠激活来源）

**⚠️ 关键错误提示**：
> "right → wrong"这类翻转，判读方向是：**激活下降 = latent 对功能敏感（不是表面）**。
> 与直觉相反：你是在测"它是否不依赖表面"，而激活下降才是"不依赖表面"的证据。

**构造要求**：与 V1 相同——必须过模型取真实激活，报 OOD 比例与显著性。

---

### V3：Token 级激活分析

**操作**：重跑推理，保存 per-token latent 激活（当前 `utterance_features.pt` 仅有 max-pooled utterance 级，**需要新的推理 pass**）。

**目的**：定位 latent 激活来自句子中的哪个 token 位置。

**输出**：
- 每条 top_activating 样例的 token-level 激活热图
- 高激活 token 的 POS / surface category 统计（是否集中在特定词类/标点）

**⚠️ 混淆提示（必须在报告中声明）**：
> 某 token 位置激活高，并不等于"该词触发了 latent"。Transformer 中每个 token 的激活聚合了前文上下文（attention + residual stream）。Token 分析只是**定位线索**，不是因果归因。
> 若需更强定位，需做"打乱上下文"或"逐步 prefix ablation"对照（属于 P5 范畴）。

---

## 5. 阴性对照（整个流程的护栏，必须执行）

以下两条对照缺失，则任何正向结论均无法排除零假设。

### 对照 A：Shuffled-Latent Baseline

**操作**：把 latent 激活在 utterance 间随机打乱（打破 latent-utterance 对应关系），重跑所有指标。

**判读**：
- 若 shuffled 下指标 ≈ 原始指标 → **latent 无贡献**，所有结论撤回
- 若 shuffled 下指标显著下降 → latent 携带了有效信息，正向结论站得住

### 对照 B：Label-Definition-Only Baseline（针对 code_discrimination 任务）

**操作**：只给 AI 看标签定义（不给任何 latent 派生解释），让它对相同测试句做分类。

**判读**：
- 若基线准确率 ≈ 或 ＞ latent 解释准确率 → latent 对分类无增量贡献，code_discrimination 指标无效
- 若 latent 解释显著超过基线 → latent 解释有增量价值

## 6. 指标汇报规范

| 任务 | 主指标 | 禁用指标 | 原因 |
|---|---|---|---|
| Latent 激活可分性 | AUC | 单独用 Cohen's d | 零膨胀分布下 d 不稳定 |
| Task B activation_prediction | accuracy, F1, balanced_accuracy（**按 task_type 拆开**） | 合并两类任务的 overall accuracy | 两类任务测量不同构念 |
| Task B code_discrimination | accuracy, F1, balanced_accuracy（**按 task_type 拆开**）| 合并 | 同上 |
| AUROC（Task B） | 辅助参考 | 主指标 | confidence 几乎恒为 0.85，AUROC 失效 |
| 反事实验证 | paired Wilcoxon / t-test + effect size | 只报均值 | 需报显著性和方向 |

> **Task B 汇报铁律**：activation_prediction 和 code_discrimination **必须分开报告**，禁止合并成单一 accuracy。前者服务 RQ1（latent 输入选择性），后者服务标签关系；混合会摧毁两个问题的区分。

## 7. Final Status 分类规则（修订版）

**现行三分法**（`robust_code_candidate / mixed_unclear / surface_artifact`）存在问题：三类并非互斥，且由单一 LLM 判定，无实证基础。

**建议改为多轴评分**：

| 轴 | 操作化 | 取值 |
|---|---|---|
| `surface_boundness` | V1 释义测试：激活下降幅度 | 0–1（高=表面绑定） |
| `function_consistency` | V2 功能翻转：激活下降幅度 | 0–1（高=功能敏感） |
| `artifact_explained` | 长度/标点/重复模板能否预测激活 | low / medium / high |
| `evidence_quality` | 解释一致性 + 跨模型稳定性 | low / medium / high |

根据轴组合下结论，而非塞进单一桶。在 V1/V2 验证未完成前，`final_status` 保持 `manual_draft`，不得报告为"已判定"。

## 8. 结论表述规范

### 允许写的

```
"The SAE latents expose auditable candidate patterns associated with MISC counselor behavior labels."

"Question-related labels (QUO/QUC) show clearer surface-functional regularities."

"Reflection labels (RES/REC/RE) require additional client context for stronger interpretation,
 as the current dataset contains only the counselor's current utterance."

"Latent X shows input selectivity consistent with [pattern description],
 and this pattern is not fully explained by surface form (V1: paraphrase test, p = ...)."
```

### 禁止写的

```
❌ "This latent is a QUO feature."
❌ "The SAE proves the model understands MISC."
❌ "Latent X equals the clinical concept of Reflection."
❌ "Top activating examples demonstrate a causal mechanism."
❌ "We have shown this is a dialogue-function feature."  ← 除非 V1 + V2 都完成且显著
```

## 9. 当前已知限制清单（论文必须声明）

| 限制 | 影响范围 | 可否后续解决 |
|---|---|---|
| 缺 client 前句 | RE/RES/REC 的 reflection 解释无法验证 | ✅ 补数据后可改善 |
| SAE 层覆盖固定（layer 19） | 无法自由选"最强层" | ⚠️ 依赖 SAE 发布计划 |
| max-pool utterance 聚合 | 偏向 surface/token 触发特征 | ✅ 补 per-token 推理 |
| 重复文本约 1214 条 | top_activating 容易出现模板 artifact | ✅ 去重/降权可缓解 |
| Task B confidence 坍缩在 0.85 | AUROC 失效 | ⚠️ 需改 calibration 设计 |
| 全流程单一 LLM 判定 | 无人工锚点，无跨模型稳定性 | ✅ 人工审核 + 多模型 |
| RE/QU 是父标签（bundle） | 探针测的是复合标签 | ⚠️ 只在 leaf 标签做主结论 |

## 10. 建议执行优先级

**第一批（pipeline 跑通 + 方法验证）**

优先标签：**QUO / QUC / AF**
- QUO/QUC：边界最清晰，适合做释义改写和功能翻转的完整 case study
- AF：肯定类关键词翻转（V2）最直观，适合方法验证

**第二批（铺开到其余标签）**

- GI / SU：功能解释相对清晰
- RES / REC / RE：需等补入 client context 后再做强解释

**始终并行**

- Shuffled-latent baseline（对照 A）：第一批就必须跑
- Label-definition baseline（对照 B）：第一批就必须跑
