# AUC / Cohen's d 交叉验证实验计划

> 目标：把现有 label-latent 关联指标从"全量单次快照"升级为"可复现、可信区间、无泄漏"的可审计证据。
> 更新：2026-07-03

---

## 1. 当前问题（为什么要做这些实验）

现在的 AUC / Cohen's d 计算路径（`eval_functional.py → univariate_analysis()`）在**全量 6194 条**上一次性算完，存在三个可信度缺口：

| 缺口 | 具体问题 | 后果 |
|---|---|---|
| **数据泄漏** | 随机 StratifiedKFold 没有按 `source_file` 分组 | 同一咨询会话的句子跨越 train/test，性能虚高 |
| **重复文本** | ~1214 条重复 `unit_text` 未去重 | 相同句子同时出现在 train/test，指标被重复样本拉高 |
| **无可复现性检验** | Top20 latent 在独立 split 上从未验证 | 无法排除 winner's curse（32768 latent 里最大噪声） |
| **无 CI** | 效应量只有点估计 | 不知道 d / AUC 的估计方差，SU(222) / RES(516) 尤其不可信 |

---

## 2. 实验总览

| 实验 | 关键操作 | 输出指标 | 优先级 |
|---|---|---|---|
| **E0 地基：去重 + 分组 CV 框架** | 建 dedup_group_id + GroupKFold | 分组键映射表 | 🔴 必须先做 |
| **E1 TopK split-half 可复现性** | 独立两半各算排名 + Top20 Jaccard | Spearman ρ、Jaccard、null 对比 | 🔴 核心实验 |
| **E2 效应量 bootstrap CI** | bootstrap on grouped sample | d 和 AUC 的 95% CI | 🟡 报告必须 |
| **E3 跨质量 split 验证** | high 上选 TopK → low 上验 AUC | cross-split AUC drop | 🔴 排除源混淆 |

---

## 3. E0：地基 —— 去重 + 分组 CV 框架

### 3.1 问题

`eval_functional.py` 现在用 `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`，没有考虑：
- 同一 `source_file` 里的句子在语言风格上高度相关；
- ~1214 条完全重复的 `unit_text`（不同 record_id，相同文本）。

已有 `full_representation_probe.py` 用了 `StratifiedGroupKFold`，说明项目有这个能力，只是没有统一到 `univariate_analysis()` 路径。

### 3.2 方法

**Step 1：建立 dedup_group_id**

```python
# 在 label_matrix.csv 上执行
df["text_normalized"] = df["unit_text"].str.strip().str.lower()
df["dedup_group_id"] = df.groupby("text_normalized").ngroup()
# 结果：~5392 个唯一文本组 + ~802 个重复文本各自归一组
```

**Step 2：两种分组键，按分析目的选择**

| 分组键 | 适用场景 | 优先级 |
|---|---|---|
| `dedup_group_id` | 去除重复泄漏，保留 source 相关性 | 默认选项 |
| `source_file` | 同时排除会话内相关性 | 更严格，推荐于发表版本 |
| `source_file + dedup_group_id` 组合 | 两者都排除（最严格）| 论文主结论 |

**Step 3：把 GroupKFold 注入到 univariate_analysis()**

```python
# 新增参数
def univariate_analysis(
    re_features, nonre_features,
    group_ids=None,          # 新增：utterance-level group ids
    n_folds=5,
    fdr_alpha=0.05,
) -> pd.DataFrame:
```

当 `group_ids` 非空时，改用 `GroupKFold`（不需要 stratify，因为 univariate 已经是 one-vs-rest 全量）。

### 3.3 输出

- `outputs/cross_val/dedup_group_mapping.csv`：每条 utterance 的 dedup_group_id
- 修改后的 `univariate_analysis()` 函数（向后兼容：`group_ids=None` 时行为不变）

## 4. E1：TopK split-half 可复现性（最高价值实验）

### 4.1 目标

验证"在一半数据上排名靠前的 latent，在另一半数据上是否仍然靠前"。

这是 winner's curse 的直接检验：若 32768 latent 里 top20 只是噪声峰，两个独立 split 的 Top20 集合应该几乎不重合。

### 4.2 方法

```
全量 6194 utterances
    ↓  按 source_file GroupKFold(n_splits=2, shuffle=True, random_state=42)
Split A（~3097 条）  |  Split B（~3097 条）
    ↓                         ↓
计算每个 latent 对             计算每个 latent 对
每个 MISC 标签的：             每个 MISC 标签的：
  - AUC                         - AUC
  - Cohen's d                   - Cohen's d
    ↓                         ↓
对每个 MISC 标签：
  1. Spearman ρ(A_rank, B_rank)  ← 整体排名相关性
  2. Jaccard(Top20_A, Top20_B)   ← 候选集稳定性
  3. 与 null 对比                ← 统计显著性
```

**Null model 构造**：
- 从同一 filtered pool（12758 latent）随机取两组各 20 个，重复 10000 次
- 得到随机 Top20 的期望 Jaccard 分布（均值约 `20/(2×20-k)` 其中 k≈0）
- 若观测 Jaccard 不显著高于 null → 候选集 = 噪声

**低频标签特殊处理**：
- SU(222), RES(516) 在每个 split 里只有约 111/258 正例
- 对这两个标签报告额外的"小样本稳定性警告"

### 4.3 输出

`outputs/cross_val/topk_reproducibility/`：
- `split_half_rank_correlation.csv`：各标签的 Spearman ρ + 95% CI
- `split_half_top20_jaccard.csv`：各标签 Jaccard + null mean + p-value
- `split_half_summary.md`：是否通过可复现性门槛的汇总

**门槛建议**：
- Spearman ρ ≥ 0.60 → 排名稳定（可信）
- Jaccard ≥ null + 2σ → 候选集显著高于随机

## 5. E2：效应量 Bootstrap 置信区间

### 5.1 目标

给每个 label-latent pair 的 AUC 和 Cohen's d 加上 95% CI，让读者判断哪些是稳健估计而不是点估计。

### 5.2 方法

对每个 MISC 标签：

```python
# 对 top-K（如 top100）latent 做 bootstrap
n_bootstrap = 2000
for boot_iter in range(n_bootstrap):
    # grouped bootstrap：以 source_file 为单位有放回抽样
    sampled_files = resample(unique_files, n_samples=len(unique_files))
    boot_df = concat(all rows from sampled_files)
    boot_auc[latent] = roc_auc_score(y[boot_df], activations[boot_df, latent])
    boot_d[latent] = cohens_d(pos_act[boot_df, latent], neg_act[boot_df, latent])

ci_auc = (percentile(boot_auc, 2.5), percentile(boot_auc, 97.5))
ci_d   = (percentile(boot_d,   2.5), percentile(boot_d,   97.5))
```

**关键**：bootstrap 单位是 `source_file`（群体自举），不是单条 utterance，以保留会话内相关结构。

### 5.3 输出

`outputs/cross_val/bootstrap_ci/`：
- `bootstrap_ci_by_label_latent.csv`：每个 label-latent pair 的 `(auc, auc_ci_lo, auc_ci_hi, d, d_ci_lo, d_ci_hi)`
- 集成进现有 `filtered_pool_association_matrix` 作为附加列

**报告使用**：论文表格中 Top20 latent 必须同时报点估计和 CI，CI 跨 0 的 Cohen's d 不得列为正向候选。

## 6. E3：跨质量 Split 验证（排除源混淆）

### 6.1 目标

确认 Top latent 捕捉的是 MISC 行为模式，而不是"high 质量会话 vs low 质量会话"的风格差异。

背景：`high`(4169条, 153文件) vs `low`(2025条, 99文件) 的标签分布不同（如 high 中 RE/REC 更多，low 中 GI/QUC 更多）。

### 6.2 方法

```
在 high split 上选 TopK latent（按 AUC 排名）
    ↓
在 low split 上验证同一批 latent 的 AUC
    ↓
同样做 low → high
```

**衡量 cross-split 稳定性**：
- `AUC_cross_drop = AUC_in_split - AUC_out_of_split`
- `rank_correlation = Spearman(rank_in_high, rank_in_low)`

**分类标准**：

| 结果 | 解读 |
|---|---|
| `AUC_cross_drop < 0.05` 且 rank 相关高 | 跨源稳健 → 可报为 stable candidate |
| `AUC_cross_drop ≥ 0.05` | 存在源混淆风险 → 报告中需说明 |
| 在 high 显著但 low 接近随机 | 强源混淆 → 不得进入主结论 |

### 6.3 输出

`outputs/cross_val/cross_quality_validation/`：
- `cross_quality_auc_comparison.csv`：各标签 Top20 latent 的 `(auc_high, auc_low, cross_drop)`
- `cross_quality_summary.csv`：每个标签有多少 latent 跨源稳健

## 9. 执行顺序与依赖

```
E0（建分组键 + 修 univariate_analysis）
  ↓
E1（split-half 复现，使用 E0 分组键）  E2（bootstrap CI，使用 E0 分组键）  E3（跨质量验证）
  ↓                                      ↓
```

**时间估算**（CPU，无需 GPU）：
- E0：< 5 分钟
- E1：~15 分钟（32768 latent × 9 标签 × 2 split = 约 60 万次 AUC 计算，可并行）
- E2：~30 分钟（bootstrap 2000 次 × top100 × 9 标签，可并行）
- E3：< 10 分钟

## 10. 结论判读规则（实验跑完后怎么用）

完成三个实验后，每个 latent 的候选状态按如下规则更新：

| 条件 | 候选状态 |
|---|---|
| E1 Jaccard 显著 + E3 跨质量稳健 + E2 CI 不含0 | ✅ reproducible_candidate |
| E1 或 E3 任一失败，但 E2 CI 宽但不含0 | ⚠️ uncertain_candidate（需人工审核）|
| E1 Jaccard ≈ null 或 E3 cross_drop ≥ 0.05 | ❌ 不得进主结论 |
| SU / RES 且小样本警告触发 | ⚠️ low_n_candidate（独立降级处理）|

这个状态列合并进 `p3_final_feature_cards.csv` 的 `association_metrics` 字段，替代现有的 `robust_code_candidate` 判定（后者是纯 LLM 意见）。
