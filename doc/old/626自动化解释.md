可以，这一部分就是你的 **P3：SAE feature 自动解释与人工验证模块**。它接在 P2 后面：P2 已经筛出了候选 features，P3 要回答：

> 这些 feature 到底在表示什么？
> 它们是 QUO、QUS、RES、REC、AF 等 MISC code 的真正行为特征，还是问号、句长、情绪词、复述词这类表面线索？

核心 pipeline 可以叫：

```text
Candidate SAE features
→ MaxAct examples
→ LLM 自动解释
→ input-centric scoring
→ output-centric scoring
→ MI 编码员验证
→ feature card / concept cluster
```

---

# 1. 这一部分的输入和输出

## 输入

来自 P2 的候选 features：

```text
F_QUO = {f_12, f_98, f_301, ...}
F_RES = {f_44, f_155, f_812, ...}
F_REC = {f_77, f_203, f_590, ...}
```

每个 feature 已经有：

```text
feature id
layer
SAE activation values
关联标签
统计指标
fold stability
```

例如：

| Feature | Layer | Target code | AUROC | Stability |
| ------: | ----: | ----------- | ----: | --------: |
|   f_590 |   L22 | REC         |   .78 |       4/5 |
|   f_102 |   L12 | QUO         |   .82 |       5/5 |
|   f_411 |   L18 | RES/REC     |   .75 |       4/5 |

---

## 输出

每个 feature 最后应该变成一张 **feature card**：

```text
Feature ID: L22-f590
Candidate label: REC
Auto explanation: detects counselor responses that integrate ambivalence or infer deeper meaning beyond literal repetition.
Top activating examples: ...
Negative examples: ...
Input-centric score: ...
Output-centric score: ...
MI coder judgment: complex reflection / ambivalence integration
Artifact risk: medium / low / high

```

这个 feature card 后续可以用于：

```text
聚类
manual-corpus 对齐
ablation / steering
论文 qualitative case study
```

# 2. P3 总体 pipeline

我建议设计成 8 步。

```text
Step 1. 选取待解释 SAE features
Step 2. 抽取 MaxAct examples
Step 3. 抽取 contrastive / low-activation examples
Step 4. 让 LLM 生成 input-centric explanation
Step 5. 做 input-centric scoring
Step 6. 做 output-centric explanation 与 scoring
Step 7. MI 编码员人工审核
Step 8. 生成 feature card，并给 feature 分类
```

这条线主要参考三类工作：

1. **SAE / dictionary learning 基础解释路线**：用高激活样本解释 feature。Cunningham et al. 证明 SAE features 相比 neuron/PCA 更容易解释，并能在 IOI 任务中定位因果特征。([arXiv][1])
2. **自动解释 pipeline**：Paulo et al. 构建了用 LLM 自动生成和评价 SAE feature 自然语言解释的开源 pipeline，并提出 intervention scoring 等解释质量评估方法。([arXiv][2])
3. **output-centric 解释**：Gur-Arieh et al. 指出只根据激活输入生成解释，可能无法捕捉 feature 对输出的因果作用；他们提出根据 feature stimulation 后更容易输出的 tokens 或 unembedding 结果来生成 output-centric 描述，并发现 input + output 结合效果更好。([arXiv][3])

---

# 3. Step 1：选取待解释 features

不要解释所有 SAE features。只解释 P2 里筛出的候选：

```text
1. 与目标 MISC code 显著相关的 features
2. sparse probe 选中的 features
3. cross-fold 稳定 features
4. manual-corpus shared features
5. 可能是 surface artifact 的 features
```

建议每个 code 第一版取：

```text
top 20–50 features
```

例如：

```text
QUO top 30
QUS top 30
RES top 30
REC top 30
AF top 30
```

每个 feature 都要记录：

```text
layer
feature id
target code
positive activation score
negative activation score
fold stability
P2 ranking
```

---

# 4. Step 2：抽取 MaxAct examples

MaxAct 就是：

> 找出最强激活某个 feature 的文本片段。

对于 feature `f_j`，你在训练集里找：

```text
Top-K samples by z_ij
```

其中：

```text
z_ij = sample i 在 feature j 上的 SAE activation
```

建议取：

```text
K = 20 或 50
```

每个样本最好保留：

```text
previous client utterance
counselor utterance
true MISC code
activation value
token-level activation span
session id / fold id
```

但是给 LLM 自动解释时，**第一轮不要给 true MISC code**，否则 LLM 很容易直接根据标签复述解释，造成泄漏。

---

## MaxAct 示例格式

给 LLM 看的格式可以是：

```text
Feature: L22-f590

The following counselor responses strongly activate this feature.
Do not assume any predefined label. Infer the shared pattern.

Example 1
Client: I know drinking is hurting me, but it is the only way I calm down.
Counselor: Part of you wants to stop, and another part is afraid of losing the one thing that helps you cope.
Activation: 4.82

Example 2
Client: I want to change, but I keep failing.
Counselor: You want a different life, and at the same time you’re scared that another attempt might prove you can’t do it.
Activation: 4.51
```

---

# 5. Step 3：加入 contrastive examples

只给 MaxAct examples 不够，因为 LLM 容易总结出过宽解释。

所以要同时给三类样本：

```text
A. High activation positives
B. Medium activation examples
C. Low / non-activation contrastive examples
```

更好的是加入 **hard contrastive examples**：

```text
QUO feature:
高激活 = 开放式探索问题
低激活 = QUS 封闭问题，但也有问号

REC feature:
高激活 = 复杂反射
低激活 = RES 简单反射，但也有 you / emotion words

AF feature:
高激活 = 肯定努力/能力
低激活 = 有 positive words 但不是 AF
```

这一步非常关键。Jing et al. 在用 SAE 解释语言特征时专门构造了 minimal contrast datasets 和 counterfactual sentence datasets，并用它们评估和干预 feature，这个思想非常适合迁移到 MISC code。([arXiv][4])

---

# 6. Step 4：LLM 生成 input-centric explanation

所谓 input-centric explanation，就是让 LLM 根据高激活输入总结：

> 什么样的文本会激活这个 feature？

你可以使用这个 prompt：

```text
You are interpreting a sparse autoencoder feature from a language model.

You are given examples that strongly activate the feature and examples that weakly activate it.
Your task is to infer the most specific shared pattern that explains high activation.

Do not mention the MISC label unless the evidence supports it.
Distinguish semantic/pragmatic behavior from surface cues such as punctuation, sentence length, emotion words, or repeated client words.

Return:
1. A concise feature description.
2. Evidence from high-activation examples.
3. What the feature is probably not.
4. Possible surface artifact risks.
5. A confidence score from 1 to 5.
```

输出应该类似：

```text
Description:
This feature appears to activate for counselor responses that integrate two sides of the client’s ambivalence and infer a deeper concern or motivation beyond literal repetition.

Evidence:
High-activation examples often contain “part of you... another part...”, contrastive structure, and inferred emotional meaning.

Probably not:
It is not merely a generic reflection feature, because simple paraphrases have low activation.

Artifact risks:
May partly track sentence length or contrastive markers such as “but” and “part of you”.

Confidence:
4/5
```

---

# 7. Step 5：input-centric scoring

LLM 给出的解释不能直接相信，要评分。

这里建议做两个 scoring。

---

## 5.1 Explanation predicts activation

给定解释和一批 held-out examples，让另一个 LLM 或同一个 LLM 判断：

```text
这个 example 是否应该激活该 feature？
```

然后比较预测和真实 SAE activation。

流程：

```text
feature explanation
+ held-out examples
→ LLM predicts activation score
→ compare with real z_ij
```

指标：

```text
correlation(predicted_activation, real_activation)
AUROC(high activation vs low activation)
precision@k
recall@k
```

这个思路和自动解释文献中的 explanation scoring 类似：Paulo et al. 的重点就是不仅生成解释，还要用更便宜、可扩展的 scoring 方法评价解释质量。([arXiv][2])

---

## 5.2 Code-specific explanation score

对你的项目来说，还要加一个 MISC-specific score：

```text
解释是否准确对应某个 MI 技能？
```

例如 feature 解释是：

```text
“invites the client to elaborate on reasons for change”
```

你可以检查它在 held-out examples 上是否更能预测：

```text
QUO > QUS
QUO > RES
QUO > AF
```

对于 REC：

```text
解释是否能区分 REC vs RES？
解释是否仍然成立于长度匹配、情绪词匹配负例？
```

建议报告：

| Score                       | 含义                 |
| --------------------------- | ------------------ |
| Activation prediction AUROC | 解释能不能预测 feature 激活 |
| Code alignment F1           | 解释是否对应目标 MISC code |
| Hard-negative accuracy      | 能不能区分 sibling code |
| Surface robustness          | 控制问号、句长、情绪词后是否仍成立  |

---

# 8. Step 6：output-centric explanation

input-centric 只回答：

```text
什么输入会激活 feature？
```

但机制问题还需要回答：

```text
激活这个 feature 会让模型更倾向输出什么？
```

Gur-Arieh et al. 明确指出，当前很多自动解释 pipeline 只看激活输入，可能不能描述 feature 对输出的因果作用；他们提出 output-centric 方法，利用 feature stimulation 后上升的 tokens 或直接对 feature 做 unembedding，来描述其输出作用。([arXiv][3])

---

## 6.1 Feature stimulation

对 feature `f_j` 做放大：

```text
z_j ← z_j + α
```

或者在 residual stream 中加上 SAE decoder direction：

```text
h ← h + α W_dec[j]
```

然后观察模型输出变化。

对于你的 MI 编码任务，观察：

```text
Δlogit(QUO)
Δlogit(QUS)
Δlogit(RES)
Δlogit(REC)
Δlogit(AF)
```

对于生成任务，观察：

```text
生成回复是否更像开放式问题？
是否更像复杂反射？
是否更像肯定？
```

---

## 6.2 Output-centric description

对每个 feature 生成输出侧证据：

```text
When stimulated, this feature increases probability of:
- “REC”
- “reflection”
- “part of you”
- “you feel”
- “what”
- “tell me more”
```

然后让 LLM 根据这些输出倾向生成解释：

```text
This feature appears to promote responses that frame the client’s statement as ambivalence and produce complex reflective summaries.
```

对比 input-centric 解释：

```text
Input-centric:
Feature activates on counselor utterances integrating ambivalence.

Output-centric:
Feature promotes REC label and complex reflection style in generated counselor responses.
```

如果两者一致，解释可信度提高。

如果两者不一致，就要小心：

```text
input says: emotion reflection
output says: generic positive sentiment
```

这说明 feature 可能不是你以为的 MI 技能 feature。

# 9. Step 7：MI 编码员人工验证

这一环非常重要。LLM 自动解释只能算初稿，不能当最终标注。

你需要让 MI 编码员看：

```text
1. feature explanation
2. top activating examples
3. low activating contrastive examples
4. output-centric evidence
5. 不显示 P2 统计结论，避免诱导
```

然后让编码员判断：

```text
A. 该 feature 是否对应某个 MISC code？
B. 如果对应，是 code-specific 还是 family-level？
C. 是否只是表面线索？
D. 是否可解释为 MI 技能子概念？
```

建议人工标签分类如下：

| 人工判断类别           | 含义                                           |
| ---------------- | -------------------------------------------- |
| Code-specific    | 明确对应 QUO、REC、AF 等特定 code                     |
| Family-level     | 对应 question-general、reflection-general 等家族特征 |
| Subskill         | 对应更细粒度技能，如 ambivalence integration           |
| Surface artifact | 问号、句长、情绪词、重复客户词                              |
| Topic/style      | 话题或咨询师风格                                     |
| Unclear          | 无法稳定解释                                       |

对于 REC，人工编码员可能会标：

```text
complex reflection - ambivalence integration
complex reflection - inferred emotion
complex reflection - deeper meaning reconstruction
```

对于 QUO：

```text
open question - change talk elicitation
open question - elaboration invitation
surface artifact - wh-word / question mark
```

这会让你的论文从“自动解释”变成“领域专家验证的机制解释”，说服力会强很多。

# 10. Step 8：生成 feature card

最终每个 feature 输出一张标准化卡片。

模板：

```text
Feature ID:
Layer:
Target code from P2:
Candidate type:
Input-centric explanation:
Output-centric explanation:
Top activating examples:
Low / contrastive examples:
Activation prediction score:
Output effect:
MI coder label:
Artifact risk:
Final decision:
```

例如：

```text
Feature ID: L22-f590
Target code: REC
Input-centric explanation:
Activates on counselor responses that integrate ambivalence and infer deeper emotional meaning.

Output-centric explanation:
When stimulated, increases REC label logit and makes generated responses more likely to include “part of you...” contrastive reflections.

Top examples:
1. “Part of you wants to stop, and another part is afraid...”
2. “You want things to change, and you’re worried that change might cost...”

Contrastive low examples:
1. “You want to stop.” [RES]
2. “Do you want to stop?” [QUS]

Scores:
Activation-prediction AUROC = .81
REC-vs-RES hard-negative accuracy = .74
Δlogit_REC after stimulation = +0.42

MI coder judgment:
Complex reflection / ambivalence integration.

Artifact risk:
Medium; partly tracks contrastive markers and sentence length.

Final status:
Robust REC candidate, pending cluster-level ablation.
```

# 11. P3 在你的完整研究里的位置

完整链条应该是：

```text
P2: 找候选 features
↓
P3: 自动解释 + 人工验证
↓
P4: feature clustering
↓
P5: causal ablation / steering
↓
P6: manual-corpus alignment
```

P3 不负责证明因果。它负责把 feature 从：

```text
L22-f590
```

变成：

```text
“可能表示复杂反射中的矛盾心理整合”
```

然后 P5 再检验：

```text
干预这个 feature / cluster 后，REC 判断或复杂反射生成是否真的变化？
```

# 12. 对不同 MISC code 的解释重点

## QUO

要问：

```text
这个 feature 是开放式探索，还是只是问号/wh-word？
```

解释时必须放入：

```text
QUO high examples
QUS low examples
带问号但非 QUO examples
QUO 改写成陈述句 examples
```

理想解释：

```text
invites elaboration or self-reflection
elicits reasons for change
opens topic exploration
```

低质量解释：

```text
questions ending with question marks
sentences starting with what/how/why
```

---

## QUS

要问：

```text
这个 feature 是封闭式确认/事实询问，还是普通问题形式？
```

high examples 应该包括：

```text
Do you...
Are you...
Have you...
How many...
```

contrast examples 应该包括 QUO。

---

## RES

要问：

```text
这个 feature 是简单反射，还是仅仅重复客户词？
```

必须加入：

```text
RES high examples
REC contrast examples
高 lexical overlap 但非 RES examples
```

理想解释：

```text
low-inference paraphrase of client content
simple reflection of stated feeling or meaning
```

风险解释：

```text
repeats words from previous client utterance
starts with “you”
```

---

## REC

要问：

```text
这个 feature 是复杂反射的深层推断，还是只是句子长/情绪词多？
```

必须加入：

```text
REC high examples
RES contrast examples
length-matched non-REC examples
emotion-word matched non-REC examples
```

理想解释：

```text
integrates ambivalence
infers unstated emotion
reconstructs deeper meaning or motivation
```

---

## AF

要问：

```text
这个 feature 是肯定来访者努力/能力，还是只是正向词？
```

必须加入：

```text
AF high examples
positive-word non-AF examples
RES/REC with positive emotion examples
```

理想解释：

```text
affirms client strength, effort, commitment, or values
```

风险解释：

```text
positive sentiment words
compliments in general
```

# 13. 最小可行版本

你第一版可以这样做：

```text
每个 code 选 top 20 features
每个 feature 抽取：
- top 20 MaxAct examples
- 10 sibling-code contrast examples
- 10 surface-matched contrast examples

每个 feature 生成：
- input-centric explanation
- output-centric explanation
- artifact risk
- MI coder judgment

每个 feature 计算：
- activation prediction AUROC
- hard-negative explanation accuracy
- Δlogit target code after stimulation
```

最终每个 code 输出：

```text
5–10 个高可信 feature cards
若干 surface artifact feature cards
若干 unclear feature cards
```

# 14. 论文中可以这样写

> For each candidate SAE feature identified in the contrastive feature discovery stage, we extracted the top-activating counselor utterances together with hard-negative and surface-matched contrastive examples. We first generated input-centric feature descriptions using an LLM, asking it to infer the shared pattern among high-activation examples while explicitly distinguishing pragmatic MI behavior from surface cues such as punctuation, length, lexical overlap, and sentiment words. We then evaluated the descriptions on held-out examples by testing whether the explanation could predict feature activation and distinguish the target MISC code from sibling and surface-matched negatives. To capture the functional role of each feature, we further generated output-centric descriptions by stimulating the feature and measuring changes in target-code logits and generated counselor responses. Finally, MI-trained annotators reviewed the feature descriptions, MaxAct examples, contrastive examples, and output effects to assign each feature to code-specific, family-level, subskill, surface-artifact, or unclear categories.

中文就是：

> 对于对比式特征发现阶段筛出的每个候选 SAE feature，我们抽取其最高激活的咨询师话语，并同时构造同家族负例和表面匹配负例。首先，我们使用 LLM 根据高激活样本生成 input-centric 特征解释，要求其区分真正的 MI 行为功能与问号、句长、词汇重合、情绪词等表面线索。随后，我们在 held-out 样本上检验该解释是否能够预测 feature 激活，并能否区分目标 MISC code 与同家族或表面匹配负例。为了捕捉 feature 的输出功能，我们进一步通过 feature stimulation 观察目标 code logit 和生成咨询师回应的变化，生成 output-centric 解释。最后，由熟悉 MI 编码体系的人工编码员审核 feature 解释、MaxAct 样本、对照样本和输出效应，并将 feature 分类为 code-specific、family-level、subskill、surface artifact 或 unclear。

# 15. 推荐引用文献

这一节主要引用这几篇：

1. **Cunningham et al., 2023/ICLR 2024, Sparse Autoencoders Find Highly Interpretable Features in Language Models**
   支撑 SAE feature 可解释性、monosemantic feature、以及通过 SAE features 做更细粒度因果定位。([arXiv][1])

2. **Paulo et al., 2024, Automatically Interpreting Millions of Features in Large Language Models**
   支撑 LLM 自动生成 SAE feature 解释、解释质量评分、intervention scoring、feature explanation 大规模自动化。([arXiv][2])

3. **Gur-Arieh et al., 2025, Enhancing Automated Interpretability with Output-Centric Feature Descriptions**
   支撑 output-centric explanation：只看输入激活不够，还要看 feature 对输出 token / 模型行为的作用。([arXiv][3])

4. **Jing et al., 2025, Sparse Auto-Encoder Interprets Linguistic Features in Large Language Models**
   支撑 minimal contrast dataset、counterfactual dataset、feature intervention confidence 这类设计，可迁移到 QUO/QUS、RES/REC、AF/non-AF 的对照解释。([arXiv][4])

---

一句话总结：
**P3 的目标不是“让 LLM 给 feature 起名字”，而是把每个候选 SAE feature 变成经过 MaxAct、对照样本、输入侧评分、输出侧评分和 MI 编码员审核的 feature card。** 这样后面你做聚类和因果干预时，才不会是在操作一堆看不懂的 feature id，而是在操作“开放式探索”“复杂反射中的矛盾整合”“AF 中的努力肯定”这类可解释候选机制。
